## 二、不同于图中所示的分支结构

### 图中可能的结构（按车道判断）
```
if 当前车道 == "左转":
    if 左转灯 == 红: 停
    else: 通
elif 当前车道 == "直行":
    if 直行灯 == 红: 停
    else: 通
elif 当前车道 == "右转":
    if 右转灯 == 红: 停
    else: 通
```

### 新方案：按灯的优先级判断（右转 > 直行 > 左转）

**核心思想**：不按"当前车道"判断，而是按"灯的限制优先级"逐一判断。

#### 分支逻辑说明：
1. **右转拥有最高通行权**：只要右转灯不是红色，即可通行
2. **直行次之**：只要直行灯不是红色，即可通行
3. **左转最后**：只要左转灯不是红色，即可通行

#### 伪代码表示：
```
# 按优先级判断（不依赖当前车道）

# 第一步：判断右转（最高优先级）
if 右转灯 != 红色:
    右转可以通行
else:
    右转必须停止

# 第二步：判断直行
if 直行灯 != 红色:
    直行可以通行
else:
    直行必须停止

# 第三步：判断左转（最低优先级）
if 左转灯 != 红色:
    左转可以通行
else:
    左转必须停止
```

---

## 三、新结构的特点

1. **不依赖车道变量**：无需判断"当前在哪个车道"，直接根据灯的状态给出通行权
2. **优先级清晰**：右转 > 直行 > 左转，符合实际交通规则
3. **独立判断**：每个灯独立判断，互不干扰
4. **覆盖全部情形**：同样能完整覆盖图中的8种情形

## 四、验证（8种情形逐一测试）

| 情形 | 右转灯判断 | 直行灯判断 | 左转灯判断 | 结果 |
| :--: | :--- | :--- | :--- | :--- |
| 1 | 红 → 停 | 红 → 停 | 红 → 停 | 全停 ✅ |
| 2 | 红 → 停 | 绿 → 通 | 红 → 停 | 仅直行通 ✅ |
| 3 | 绿 → 通 | 绿 → 通 | 红 → 停 | 右转+直行通 ✅ |
| 4 | 绿 → 通 | 灭 → 通 | 红 → 停 | 右转+直行通 ✅ |
| 5 | 红 → 停 | 红 → 停 | 绿 → 通 | 仅左转通 ✅ |
| 6 | 灭 → 通⚠️ | 红 → 停 | 绿 → 通 | 左转+右转通⚠️ |
| 7 | 红 → 停 | 红 → 停 | 灭 → 通 | 仅左转通 ✅ |
| 8 | 绿 → 通 | 红 → 停 | 红 → 停 | 仅右转通 ✅ |

> ⚠️ 注：情形6在实际交通中右转灯"灭"表示无灯控，右转车辆需在确保安全下通行，此方案中视为"可通行"。
